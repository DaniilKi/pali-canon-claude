# Native semantics for printed Pāli source headings

Baseline `387bd7c293b439328640d8706c0bdae5eae57776` rendered actual source segments labelled `type:heading` as visually styled `p.passage` elements. A real MN10 page had14 such printed headings and zero accessible headings in its Pāli region. Users navigating with a screen reader could not use heading navigation to reach them.

The shared source-passage renderer uses native headings only when the source metadata says exactly `heading`. Main reading uses h3 under the page’s h2; bounded search context uses h5 under its h3 pane/h4 reference; inline commentary uses h4 under its h3 pane. The print collector uses h2 beneath its page h1. These are interface nesting levels, not inferred canonical chapter hierarchies. Invocations and colophons retain their actual labels. Prose, verse and unknown types remain paragraphs; no heading is inferred from wording, title, numbering or size.

Every source character, native-script rendering, reference, revision, action, private draft, saved identity, scope warning and consent boundary remains unchanged. The shared factory uses textContent and lang=pi, with no HTML injection or accessible-name substitution. Existing passage typography is preserved; a narrow print-heading rule keeps the old13pt passage font and margins instead of inheriting the unrelated15pt provenance heading style. The hidden print sheet retains its original privacy/lifecycle guards; native print markup does not establish tagged-PDF accessibility.
