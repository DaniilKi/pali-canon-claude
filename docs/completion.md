# Completion criteria and current gaps

This project retrieves the VRI Pāli edition. Completion means readers can reliably reach every promised passage, continue to its end, identify its source and limitations, and use the packaged server in the supported clients. It does not mean that an English translation exists for every text or that machine-generated scripture can fill a gap.

## Run the exhaustive reading check

```sh
npm ci
npm run check
npm run corpus:check -- --report corpus-check.report.json
```

The default scope is `all`: canon, commentary, post-canonical books and complete VRI root-book readings. It runs the built `server/index.cjs` over MCP stdio with every allowlisted online source simulated as unavailable. It compares the structured response with the JSON text response, and every returned segment with the local source representation. Reports include source coverage, collection totals, checked entries, pages, segments, a semantic SHA-256 fingerprint and failures. A failure exits non-zero. A selected scope is explicitly labelled `passed_selected_scope`, never a pass for the entire corpus.

Use `--scope canon`, `--scope commentary`, `--scope postcanonical` or `--scope books` to diagnose a section; use `--page-size 17` to exercise different continuation boundaries. `--server <path>` selects a different built stdio server. The checker uses the source data in the current checkout as its baseline, so that source must represent the same intended corpus as the server under test. A fingerprint is meaningful only for the same scope and source version. Segment fingerprints are independent of page size and compressed-file boundaries.

The checker confirms faithful retrieval of the bundled representation. It shares segmentation/resolution code with the source and does not independently prove that every editorial boundary or manuscript reading is correct. Keep the full audit, source provenance, citation evidence, licensing rules and scholarly review in addition to this check.

The original 5 November 2026 local baseline passed with 8,544 canonical checks, 8,544 commentary checks and 109 post-canonical book checks: 21,302 pages and 378,651 returned segments, zero failures, and zero unreachable numbered body blocks. Segment totals count each requested unit and include shared/grouped passages; they are not a count of distinct passages. The original three-scope semantic SHA-256 is `3d69bcd5da4edfcb4b2316989987d01089476ae5beb77409eba2d224b9d38709`; an `all` run retains it as `indexed_texts_sha256` before adding whole-root-book checks to the overall fingerprint. This is a Roman-script retrieval baseline for VRI commit `2d134ff9ef60f70a1eb03c9370580228811a3070`, not a certification of every live provider, script or client.

The subsequent complete-book reading cycle passed all four scopes: the same indexed-text checks plus all 61 complete VRI root books, totalling 23,529 pages and 510,404 returned segments, zero failures. The overall semantic SHA-256 is `9a19b37ea60700c3dc74373efbfb8cdc2c0b99021ade521ecd596593bc69b8b7`; `indexed_texts_sha256` still exactly matches the original baseline. Source-book views repeat the canonical content in a different reading mode, so these totals include that additional view. Seven new regression tests cover the previously uncited openings, source references, continuations, variants/scripts and invalid or mixed selectors. The standard gates passed 389 tests (one live test skipped), the full audit, 57 offline smoke checks and 195 offline evaluations (six live questions skipped).
