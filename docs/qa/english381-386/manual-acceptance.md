# Remaining manual reader acceptance

Automated Chromium, Firefox or WebKit runs and emulated mobile viewports do not replace these checks. Record the exact dev commit, device model, OS, browser and result. Use synthetic study data, not a person's private notes. A blank result means not performed.

| Environment | Journey | Evidence to record | Status |
| --- | --- | --- | --- |
| Physical iPhone and iPad, Safari | First visit → Apadāna → publisher 381 and 384; change orientation, open notes, follow a Pāli quotation and return | Text and controls remain readable; source identity and the published note-4 caveat remain visible; no lost position | Not performed |
| Physical Android phone, Chrome | Same journey; background the browser, reopen, continue a long poem and reload | Position, selected edition and saved synthetic notes survive as documented; no invented offline availability | Not performed |
| Human VoiceOver and TalkBack users | Navigate headings, choose a source, read/open/close a note, return to the invoking control | Understandable names and reading order; useful focus restoration; all operations reachable | Not performed |
| Human desktop screen-reader and keyboard user | Search, follow an exact citation, open a long note, export and re-open a synthetic bookmark | No keyboard trap, stale focus steal, silent rebasing or loss of attribution | Not performed |
| Authorised signed-in external host | Open the reader through the actual host integration and continue a source-pinned passage | Host tools and resource versions agree; consent, source boundaries and citation identity remain intact | Not performed |

Check both an unchanged earlier choice and a new choice. A complete publisher-edition poem is not a claim of a line-complete VRI translation. Do not clear rights or alignment holds as part of usability testing. Do not upload real study notes, credentials or transcripts when reporting a defect.

Record failures as separate reproducible issues with expected versus observed behaviour. A successful automated run establishes only the environment and assertions in its receipt; it must not fill any row in this table automatically.
