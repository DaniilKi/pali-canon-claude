# Short remaining hands-on checks

These checks are **not completed**. Automated browser tests, viewport emulation,
and accessibility scanners do not substitute for them. Use a reviewed candidate
or accepted dev build, record its exact Git commit, and use disposable notes.
Do not publish or change production to perform this checklist.

## A phone and a tablet — about eight minutes

Use actual devices with their installed browsers. Record each device, OS,
browser version, and commit. On the phone, open Library → Apadāna → reviewed
publisher edition. Open Tissametteyya and Puṇṇaka, then switch back. Check that
the selected poem, Pāli citation, publisher number, and English version agree.
English should open only after the reader asks for it.

Read the speaker labels, the separate chapter heading, and several long notes.
Enlarge text, rotate the device, and confirm that no words, buttons, or notes are
cut off. Follow the publisher link and return to the same reading context.
On the tablet, repeat selection and long-note scrolling in landscape and portrait.

Save one passage with a disposable note. Reload, reopen it from Saved, and export
the saved record. Confirm the note and exact passage remain intact. A historical
389/390 positional record should request review while remaining available in
Saved/export; it should not silently move its note to different words.

## A person using a screen reader — about five minutes

Use VoiceOver, TalkBack, or NVDA with a person who can assess its output. Record
the actual browser and assistive technology versions. Check the Library and
source selectors, reading order, source/edition announcements, note numbers,
focus after navigation, and the historical-position review message. Confirm
that loading a response does not interrupt another input the person has selected.

## A signed-in assistant host — about five minutes

Use the intended signed-in Codex, Claude, or ChatGPT host and its actual connector
configuration. Retrieve `tha-ap403` and `tha-ap404`, request the named publisher
version, and follow a continuation. Check exact source identity, attribution,
licence, and edition caveats. If the host supports the reading widget, check its
real rendering separately. Do not infer host acceptance from a simulated bridge.

## Record the result

For each session, record commit, device/host, versions, checks attempted, actual
results, and any reproducible failure. Redact account identifiers and personal
notes from evidence. A loaded page's offline Saved behavior does not establish
first-run offline installation or an offline browser/PWA capability.
